# ST ImageGen

SillyTavern 生图扩展。仅调用现有 `comfy-gen-service` 接口，提供四项功能：

- 浮窗：拖动、缩放、最小化、位置记忆，关闭窗口不取消后台任务。
- 提示词编辑：填写画面要求、单独生成提示词、修改正负提示词后绘图。
- 进度：查询原服务任务状态和进度，完成后展示图片；失败明确提示，不自动重复提交。
- 插图：通过酒馆原生上传保存图片并插入发起任务的聊天；切换聊天或聊天正在生成时暂存，避免插错。

手动生图仅使用填写的要求。自动模式经用户开启后参考最近N条用户/角色文本，不读取角色卡或主聊天预设；不需要imagegen用户或API Bridge会话。提示词模板完全由现有接口管理，本仓库没有 Anima/Krea 模板、提示词扩写规则或 LLM SDK。

## 目录

- 根 `manifest.json`、`extension/`：可按 Git 仓库方式安装的酒馆前端。
- `server/`：酒馆服务端传输插件，只转发现有业务接口；服务凭据保留在服务器，任务访问按酒馆账号隔离。
- `tests/`：接口调用、任务隔离、浮窗交互、编辑/轮询/插图验证。

## 服务端安装

1. 将 `server/` 中的文件放入 SillyTavern 的 `plugins/stimagegen/`。启用酒馆 server plugins。
2. 将 `stimagegen.config.example.json` 复制为酒馆 `config/stimagegen.json`，填写服务的受限调用凭据，限制权限为600。也可用 `STIMAGEGEN_CONFIG` 指向此配置。
3. 设置 `imageService.defaultWorkflow` 为服务返回的某个工作流 key。留空时在浮窗首次选择，之后自动记住。插件不设置尺寸、步数、模型或修改工作流。
4. 确保酒馆服务器能访问 `https://comfy.nihilhhl.lol`。这里连接的是生图服务，由服务继续经服务器 SSH 隧道访问 Colab ComfyUI。
5. 重启酒馆加载服务端插件；安装本仓库前端后刷新页面。在扩展设置点“打开生图窗口”，或点击聊天旁“生图”。

配置里的 `promptMode` 默认为 `natural`，仅映射现有接口的 mode 字段；没有附加提示词模板。若服务实际使用 tags 模式管理模板，可配置为 `tags`。

现有生图服务的集成凭据必须允许下列接口。此前 `stbridge.key` 的服务授权仅允许工作流、绘图和图片读取，**尚不包含 `/api/prompts/generate`**；服务管理员需为同一集成凭据补充该单一 POST 路径授权，或提供已有相应权限的凭据。不要把网页登录密码或凭据填入前端。这里不创建新的业务接口、不迁入服务端 LLM 实现。

酒馆原生中间件负责登录和 CSRF。前端只访问同源 `/api/plugins/stimagegen/service`，由服务端按固定 URL 转发。Nginx 如果存在较短超时，需给这一路由设置至少150秒的读取超时和足以容纳图片响应的限制；不要因此关闭酒馆登录或CSRF。

## 使用

1. 打开浮窗，填写“想画什么？”，首次刷新并选工作流。
2. “只生成提示词”得到服务返回的正负提示词，可在“调整提示词”中编辑。
3. “用当前提示词绘图”只提交编辑后的提示词；“生成图片”连续执行提示词生成和绘图。
4. 图片完成后自动放入原聊天；若切换聊天，返回原聊天后点“插入图片”。重复点击不会再次插入。

手动填写正向提示词后也可直接绘图，不要求先调用 LLM。关闭浮窗后可由扩展设置重新打开，当前页任务仍继续。刷新或关闭整个酒馆页面会丢失面板内存状态，任务仍在生图服务图库，不会取消或删除。

若旧 API Bridge 生图入口仍启用，可能同时看到两个按钮。迁移阶段可停用旧版生图面板；本仓库不会修改旧桥接插件或线上配置。

## 现有接口映射

| 操作 | 服务接口 |
| --- | --- |
| 生成提示词 | `POST /api/prompts/generate`，只发送 requirement 和 mode |
| 工作流 | `GET /api/workflows` |
| 提交绘图 | `POST /api/jobs` |
| 查询状态 | `GET /api/jobs/{id}` |
| 获取图片 | `GET /api/images/{id}/{index}` |

提示词响应要求 positive、negative 为字符串，summary_zh 可省略。任务和图片响应沿用现有接口。原服务的密钥、模板、历史记录和图片未迁入仓库。

## 验证

Node.js 20+：运行 `npm test` 和 `npm run check`，无额外 npm 依赖。测试使用隔离服务响应和模拟 DOM，不访问真实模型、不提交 GPU 任务；真实酒馆主题、动画和服务连通仍需安装后验证。

许可证：AGPL-3.0-only。浮窗和生图客户端从原 st_prompt_extension 中独立整理。


## 自动生图（1.1.0）

在浮窗展开“自动生图”，选择：

- **关闭**：默认值；没有后台LLM或绘图调用。
- **由LLM判断**：每条新角色回复结束后，服务根据选定的最近消息判断是否值得配图；明确返回true才继续生成提示词和图片。普通闲聊或相似画面可被跳过。
- **每N条角色回复生成一次**：N默认5，可设1–100。按新角色回复计数，用户消息不计数；图片消息、历史加载、重复事件和重生成同一条回复不计数。

“参考最近消息数”默认4，可设1–20，包含你与角色的文本。超过12000字符会提示减少条数，不静默截断。设置按酒馆账号保存，计数按聊天保存；开启或切换设置时从当前聊天建立基线，不补画历史消息。

自动任务串行执行，不无限排队；LLM判断失败或返回格式错误不会提交图片，失败不自动重放。切换聊天或更改自动设置后，尚未提交的旧场景会被丢弃；已经提交的任务照常保留，插图仍检查原聊天。支持Web Locks的浏览器对同账号同聊天的多标签页执行互斥。

### 服务接口兼容

仍使用 `POST /api/prompts/generate`。普通请求不变；增加可选字段：

```json
{"requirement":"选定消息的JSON文本","decision_only":true,"previous_summary":"上次自动配图摘要，可为空"}
```

判断响应：

```json
{"should_generate":false,"reason":"没有新的可见场景"}
```

插件内部`decide`操作只转发该模式，不新增LLM SDK或图像提示词模板。服务端可选判断实现见`integration/image_decision.py`，复用服务已有`llm.chat_completion`与配置。服务的PromptReq需增加`decision_only: bool=False`及`previous_summary: str=''`；gen_prompts在普通生成前检测decision_only并调用decide，不保存判断结果为提示词历史。

线上已完成此兼容更新。部署记录见 `docs/auto-generation-2026-11-03.md`。源码测试与模式校验不代表真实LLM判断和出图已验证，上游仍需正常连通。

主模型选择：在“工作流与偏好”选择工作流后，通过现有 `/api/workflows/detail` 读取 `main_model`，展示工作流默认文件和已安装模型列表。选择按酒馆用户、工作流保存；手动与自动生图通过 `params.main_model` 提交。不支持切换的工作流沿用原配置；模型列表失败或已保存模型失效时不提交绘图。模型列表按加载器类型提供，选择时仍需匹配工作流架构。

手动生图：画面要求可留空，默认参考当前聊天最近4条有效用户/角色文本消息（不足4条则使用已有消息），跳过系统消息和纯图片消息。填写要求时仅使用填写内容。“生图”“生成图片”“只生成提示词”均遵循此规则；自动模式的参考条数设置不影响手动默认值。无有效消息、聊天仍在生成或参考消息超长时显示提示，不提交空请求。

模型路由：默认由现有服务 LLM 根据当前参考消息/画面要求选择 Krea 写实或 Anima 二次元，Anima 优先使用当前可用 Turbo 工作流及文件；未安装时才使用可用非 Turbo。也可指定 Anima、Krea 或手动选择。手动改工作流/模型立即持久切换为手动。提示词生成传入实际工作流和模型，复用服务端现有模型模板。分类失败、模型缺失时提示错误，不提交绘图。

打开浮窗的防重复规则：按聊天记录上次成功生图对应的文本消息数；有至少1条新增有效文本消息时，点击聊天按钮或设置启动器才自动生成；没有则仅打开浮窗并显示计数。手动“生成图片”可强制重画。用户/角色文本都计数，系统消息、纯图片和仅编辑旧消息不计新增。生成期间到来的消息保留为新增。刷新后保留计数。首次使用将已有有效文本视为未配图。
模型判断按世界观：明确现实世界/三次元设定默认Krea，明确二次元作品背景默认Anima，显式画风要求优先；没有二次元证据默认Krea。
